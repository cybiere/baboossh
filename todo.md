# Known limitation: paramiko has no ChaCha20-Poly1305 support — baboossh cannot reach ChaCha20-only SSH servers

`paramiko`'s cipher list (`paramiko.transport.Transport._preferred_ciphers`) doesn't implement `chacha20-poly1305@openssh.com` at all. TinySSH implements *only* that cipher, so there is zero overlap and `baboossh` can never connect to a stock TinySSH server, or any SSH server restricted to ChaCha20-Poly1305 only. Not fixable via `baboossh`'s own config (would need a paramiko-side cipher implementation or switching SSH libraries). `tests/docker/` deliberately includes a ChaCha20-only container so this failure mode is exercised. Documented user-facing in `README.rst`'s "Known limitations" section.

The error-handling gap around this (an uncaught `IncompatiblePeer` traceback instead of a clean "KO") is now fixed — see "Recently closed".

# Possible UX issue: Workspace.probe() is very slow against a genuinely unreachable host

`probe()` against a host with no known/discoverable path took over 2 minutes before being killed (never finished). `probe()`'s fallback chain (`baboossh/workspace/probe.py`) tries several strategies in sequence — direct, given gateway, existing path, direct-from-local, then *every known `Host`* as a candidate gateway — each needing its own full connection timeout before falling through. Against a genuinely unreachable target, every attempt times out, so total wait scales with the number of known hosts. Not a bug (no incorrect behavior, just slow), but worth a look — e.g. shorter timeouts for exploratory fallback attempts, or surfacing progress/cancellation.

# Recently closed

- **`Connection.identify()` stored shell error text as real field data** — `identify()` only checked the exit code of the `hostname` command; the exit codes of `uname -a`, `cat /etc/machine-id`, and the MAC-gathering pipeline were ignored, and their raw `result` string was stored regardless of success. On a host without `/etc/machine-id` (common on non-systemd distros), `cat /etc/machine-id` failed and its stderr text (e.g. `"cat: /etc/machine-id: No such file or directory"`) was silently stored as `Host.machine_id`. Fixed via a new `_identify_field()` helper that redirects stderr (`2>/dev/null` — `exec_command()`'s PTY merges stderr into stdout, so a failing command's error text was otherwise indistinguishable from real output) and checks the exit code for every probe, not just `hostname`. `machine_id` is now validated against a 32-hex-char pattern (with a `/var/lib/dbus/machine-id` fallback that recovers identification on non-systemd hosts that do have a dbus machine-id) and MACs are validated by regex, deduplicated, and sorted by value instead of by interface name (avoids the identity fragmenting on a NIC rename/hotplug). Failed/invalid fields now store `""`/`[]`, never error text. Also dropped a stray `print(serverKey.asbytes())` debug line. `tests/test_docker_range.py`'s `strict` xfail pinning this bug is now a plain passing regression test. Note: a separate `handoff.md` design brief proposes a much larger host-identity redesign (scored multi-signal matching, SSH host key persistence, clone detection); this fix is a prerequisite for that redesign (its "absent means absent" assumption depended on this) but does not implement it — still tracked as future work, not yet filed as its own todo entry.
